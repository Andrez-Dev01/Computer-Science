# Workflow While Reading — One Section at a Time

## Read → Document → Experiment → Apply
1. Open the specific chapter's section note.
2. Read a small paragraph or subsection.
3. Under the correct **topic** heading, capture vocabulary, methods, variations, and an explanation **in your own words**.
4. Recreate the instructional example in a coding editor, then change a value or edge case. In the note, record the short explanatory code sample, expected result, and any mistake/fix.
5. Apply it in a small program, with a brief program path/repo URL (only if safe for a public vault).
6. Continue to the next part of the section; insert another Topic Block as necessary.

## When a lecture or assignment adds something
Add it to the **relevant topic heading in the existing section note**. Use a small label such as `Lecture insight:` or `Assignment observation:` and cite the source nearby. Do not create a second notes folder just to copy it.

## Example of inline verification
**Statement:** A C++ for-loop checks its condition before each iteration.

**Source:** C++ reference/documentation link or the relevant textbook section (reference only, not copied pages).

**I tested:** Yes — ran a sample where the initial condition was false; the body ran zero times.

## Manual review — no scheduling system
When you decide to revisit a topic:
- Explain the code or concept *before* checking the note.
- Reread what you missed.
- Reimplement a tiny exercise and compare behavior.

## When to create a quick reference
Only if you find yourself repeatedly searching for the same command, syntax pattern, or technical fact. The reference should remain concise and link back to the complete source notes.
