# {{8.2.1 Stack Parameters}}

## 🎯 Learning Objectives
- Learn how subroutines can receive parameters on the stack

## 🔑 Key Concepts
### Stack Parameters
- **Definition:** A subroutine parameter that has been passed on the stack
- **Why it matters:** For Assembly in Windows its always used by the Windows API functions but must have register parameters and stack parameters
- **Example:**
### Stack frame or Activation record
- **Definition:** the area in the stack set aside for passed arguments, subroutine return address, local variables, and saved register
- **Why it matters:** 
	- It matters because we are directly affecting the programs memory model and its choice of argument passing
	- It relates to all high level programming languages 
- **Example:** If we wanted to pass arguments on the stack to call functions on a API request

## 🧑‍🏫 Notes from Section
- #### Creating a Stack Frame
	- Passed arguments if there are any pushed on the stack
	- Call the subroutine to then return the address to be pushed on the stack
	- While the subroutine works to be executed the EBP is pushed on the stack
	- EBP = ESP and from now on EBP acts as a base reference for all the subroutine parameters 
	- If we have any local variables, ESP is decremented to reserve space for the variables on the stack
	- If we have to save any registers they are pushed on the stack
